使用 `/v1/images/edits` 编辑已有图片。日常优先 `gpt-image-2.5-flare`；对细节保留、编辑精度要求更高时可选择 `gpt-image-2.5-sunburst`。

## 提供图片

| 图片在哪里 | 传入方式 |
| --- | --- |
| 已有服务端可访问的 URL | JSON：`images: [{"image_url": "https://..."}]` |
| 已有 base64 | JSON：`images: [{"image_url": "data:image/png;base64,..."}]` |
| 本地文件 | multipart：`image=@photo.png` |
| 多张参考图 | JSON 数组或重复的 `image[]` 文件字段；数量由渠道限制 |

JSON 中不能用 `file_id` 代替 `image_url`。图片的 MIME 类型应与真实文件匹配。示例代码见[图像编辑 API](/cn/api-reference/images/gpt-image-2/edits)。

## 写清修改范围

例如：“保留杯子的形状、Logo 和文字，只把背景改成浅蓝色摄影棚”。参考图数量与输出张数 `n` 是两回事；提交两张参考图并不表示一定生成两张结果。

`size` 和 `quality` 控制输出图片。2.5 可使用 `xhigh`、`max`，旧版 2.0 不使用这两个档位。`input_fidelity` 只在部分编辑通道有效，不应依赖它保证保真。

## 局部编辑

渠道支持遮罩时，可用 `mask.image_url` 或 multipart 文件字段 `mask`。使用与第一张参考图尺寸一致、带透明通道的 PNG，把要修改的区域设为透明。遮罩帮助模型定位编辑区域，不保证其他像素完全不变。

## 取回结果

同步调用读取 `data[]` 中的 `b64_json` 或 `url`，保存方法与图像生成一致。

当前公共服务未开放图片异步提交，请保持连接等待完整结果。需要流式输出时传 `stream: true`，并根据实际 Content-Type 解析，见[图片流式返回](/cn/api-reference/images/streaming)。

## 常见问题

- URL 不可访问：改为 Data URL 或直接上传文件。
- JSON 提示缺少图片：检查字段是否为 `images[].image_url`。
- multipart 解析失败：让 SDK/cURL 自动设置带 boundary 的 Content-Type。
- 透明背景没有保留：选择 2.5，输出格式使用 PNG/WebP。
- 权限或模型错误：检查当前 Key、分组图片权限和模型列表。
