---

首次接入建议使用 `gpt-image-2.5-flare`、`quality: "low"`、`size: "1024x1024"` 和 `n: 1`，确认成功后再提高质量或尺寸。

## 模型选择

| 模型 ID | 适用场景 | quality |
| --- | --- | --- |
| `gpt-image-2.5-flare` | 快速生成、日常创作；Images 接口省略 model 时的默认值 | `auto`、`low`、`medium`、`high`、`xhigh`、`max` |
| `gpt-image-2.5-sunburst` | 对细节、编辑精度要求更高的任务 | `auto`、`low`、`medium`、`high`、`xhigh`、`max` |
| `gpt-image-2` | 保留现有 2.0 工作流 | `auto`、`low`、`medium`、`high` |

请写完整的模型 ID，不要使用 `gpt-image-2.5` 作为两个模型的通用别名。使用前通过 [GET /v1/models](/cn/models) 确认当前 API Key 可见模型；模型可见还需要分组开启图片生成权限，并有可用渠道。

模型定位参考 [OpenAI Flare 说明](https://developers.openai.com/api/docs/models/gpt-image-2.5-flare)和 [OpenAI Sunburst 说明](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst)。通用图像参数参考 [OpenAI 图像指南](https://developers.openai.com/api/docs/guides/image-generation)。本平台的接口路径、权限和兼容行为以本手册为准。

## 选择接口

| 需求 | 接口 | 返回方式 |
| --- | --- | --- |
| 根据文字生成图片 | [POST /v1/images/generations](/cn/api-reference/images/gpt-image-2/generation) | 等待图片结果；可选 SSE |
| 上传参考图、编辑图片或使用遮罩 | [POST /v1/images/edits](/cn/api-reference/images/gpt-image-2/edits) | 等待图片结果；可选 SSE |
| 提交后再查询生成结果 | [POST /v1/images/generations/async](/cn/api-reference/images/async-generation) | 202 + task_id；需要服务端启用 |
| 提交后再查询编辑结果 | [POST /v1/images/edits/async](/cn/api-reference/images/async-edits) | 202 + task_id；需要服务端启用 |
| 在对话中组合文字与图片 | [POST /v1/responses](/cn/api-reference/responses) | Responses 输出；图片位于 image_generation_call |

## 尺寸和质量

`size` 使用 `auto` 或 `宽x高`，例如 `1024x1024`、`1536x1024`、`1024x1536`、`2048x1152`、`3840x2160`。宽高顺序决定横图或竖图。

这些尺寸是请求示例，不代表每个模型和渠道均接受所有尺寸。网关会将尺寸交给所选上游校验；请以返回的 `size`（如有）和图片实际像素为准。不要把创作页面里的 `1K`、`2K`、`4K` 档位或 `aspect_ratio`、`resolution` 直接作为 Images API 的尺寸参数。

`quality` 控制生成质量，`output_compression` 控制 JPEG/WebP 文件压缩。2.5 可使用 `xhigh`、`max`；旧版 `gpt-image-2` 不应照搬这两个档位。高质量、大尺寸和多张输出通常需要更长时间。

## 透明背景和输出格式

2.5 请求可以组合 `background: "transparent"` 与 `output_format: "png"` 或 `"webp"`。JPEG 不保存透明通道。`background` 还可使用 `auto` 或 `opaque`。

`output_format` 使用 `png`、`jpeg`、`webp`。输出 JPEG/WebP 时可设置 `output_compression`，常用范围为 `0`–`100`；PNG 请求省略。参数是否被接受以目标模型和渠道为准。

## 兼容字段

| 字段 | 当前使用建议 |
| --- | --- |
| `response_format` | 兼容旧客户端。官方 Images 通道会移除此字段；不要依赖它强制获得 HTTP 图片链接。客户端应兼容 `b64_json`、HTTP URL 和 Data URL。 |
| `style` | 不作为 GPT Image 2 / 2.5 的有效风格参数；将“水彩、写实”等要求写入 `prompt`。 |
| `input_fidelity` | 仅部分编辑通道接受；生成接口不会使用它，部分编辑通道也不会传递。默认省略，不能把它当作跨渠道保证。 |
| `images[].file_id`、`mask.file_id` | Images JSON 编辑接口明确拒绝；改用 `image_url` 或 multipart 文件上传。 |

`gpt-image-2` 不承诺透明背景；官方 Images 通道会移除旧模型的 `background: "transparent"`。需要透明输出时选择 2.5。

## 耗时与计费

费用以当前 API Key 所属分组的价格配置和实际用量为准。即使 Flare 与 Sunburst 使用相同基础费率，单张图片消耗也可能不同；不要把“同一费率”理解为固定单张价格，也不要套用旧模型的估价。

同步请求需要保持连接直到返回完整结果。超时或断开连接不代表上游已停止生成；避免立即重复提交。需要在应用刷新后继续查询进度时，使用已启用的图片异步任务接口。
