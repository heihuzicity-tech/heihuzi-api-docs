根据提示词生成图片。GPT Image 请求需要能访问 OpenAI 图像渠道的 API Key，并开启分组图片生成权限。省略 `model` 时默认使用 `gpt-image-2.5-flare`；建议显式填写模型。

Base URL：`https://code.heihuzi.ai`。请求使用 `application/json`，鉴权为 `Authorization: Bearer <token>`。

<RequestExample>
```bash cURL
curl --request POST \
  --url https://code.heihuzi.ai/v1/images/generations \
  --header "Authorization: Bearer $HEIHUZI_API_KEY" \
  --header 'Content-Type: application/json' \
  --data '{
    "model": "gpt-image-2.5-flare",
    "prompt": "一只橘猫坐在窗台上看夕阳，水彩画风格",
    "n": 1,
    "size": "1024x1024",
    "quality": "low",
    "output_format": "png"
  }'
```

```python Python
import os
import requests

response = requests.post(
    "https://code.heihuzi.ai/v1/images/generations",
    headers={"Authorization": f"Bearer {os.environ['HEIHUZI_API_KEY']}"},
    json={
        "model": "gpt-image-2.5-flare",
        "prompt": "一只橘猫坐在窗台上看夕阳，水彩画风格",
        "n": 1,
        "size": "1024x1024",
        "quality": "low",
        "output_format": "png",
    },
    timeout=(15, 600),
)
response.raise_for_status()
payload = response.json()
if payload.get("error") or not payload.get("data"):
    raise RuntimeError(payload)
print(payload)
```

## 请求参数

<ParamField body="model" type="string" default="gpt-image-2.5-flare">
  可选。使用 `gpt-image-2.5-flare`、`gpt-image-2.5-sunburst` 或 `gpt-image-2`。实际可用模型以当前 Key 的模型列表为准。
</ParamField>

<ParamField body="prompt" type="string" required>
  图像描述。明确主体、构图、风格及需要出现在画面中的文字。
</ParamField>

<ParamField body="n" type="integer" default="1">
  生成张数，使用正整数。上限及多张输出能力由所选模型和渠道决定；初次调用建议设为 `1`。客户端应遍历实际返回的 `data` 数组。
</ParamField>

<ParamField body="size" type="string">
  `auto` 或 `宽x高`，例如 `1024x1024`、`2048x1152`。省略时交由上游选择。详见[模型与参数](/cn/api-reference/images/models)。
</ParamField>

<ParamField body="quality" type="string">
  2.5 支持 `auto`、`low`、`medium`、`high`、`xhigh`、`max`；旧版 `gpt-image-2` 使用前四种。省略时使用上游默认值。
</ParamField>

<ParamField body="background" type="string">
  `auto`、`opaque` 或 `transparent`。透明输出请选择 2.5，并搭配 `png` 或 `webp`。
</ParamField>

<ParamField body="output_format" type="string">
  图片编码格式：`png`、`jpeg`、`webp`。此字段不控制响应是 URL 还是 base64。
</ParamField>

<ParamField body="output_compression" type="integer">
  JPEG/WebP 输出的压缩参数，常用范围 `0`–`100`；PNG 请求省略。取值由上游校验。
</ParamField>

<ParamField body="moderation" type="string">
  上游内容审核选项，例如 `auto`、`low`，仅在渠道支持时生效。不会关闭平台自身的内容审核。
</ParamField>

<ParamField body="stream" type="boolean" default="false">
  `true` 时使用 SSE 接收图片事件；需要渠道支持。见[流式返回](/cn/api-reference/images/streaming)。
</ParamField>

<ParamField body="partial_images" type="integer">
  流式预览图数量，使用 `0`–`3`；`0` 表示只接收最终图片。仅在 `stream: true` 且上游支持时有意义。实际事件数量可能少于请求数量，不等同于最终图片张数 `n`。
</ParamField>

<ParamField body="response_format" type="string">
  旧客户端兼容字段。官方 Images 通道会移除它；不要依赖 `url` 或 `b64_json` 强制控制所有渠道的响应。新请求建议省略。
</ParamField>

## 响应

非流式成功响应使用 OpenAI Images 结构。以下 base64 是占位符：

<ResponseExample>
```json
{
  "created": 1788998400,
  "data": [{"b64_json": "<base64-image-data>"}],
  "output_format": "png",
  "size": "1024x1024",
  "quality": "low"
}
```
</ResponseExample>

| 字段 | 含义 |
| --- | --- |
| `created` | Unix 秒时间戳 |
| `data[]` | 实际生成结果；处理全部元素 |
| `data[].b64_json` | 图片的 base64 数据，解码后保存 |
| `data[].url` | 部分渠道返回的 HTTP URL 或 `data:image/...;base64,...`；不一定是长期有效下载链接 |
| `data[].revised_prompt` | 可选，返回的提示词修订信息 |
| `model`、`size`、`quality`、`background`、`output_format` | 可选元信息，以实际响应为准 |
| `usage` | 可选用量信息，不能直接当作本平台最终扣费金额 |

`url` 与 `b64_json` 可能仅出现其一，也可能同时出现。保存示例见 [OpenAI SDK](/cn/integrations/openai-sdk)。非流式连接等待期间可能收到用于保活的空白字符，应在响应结束后解析完整 JSON。首次保活会提交 HTTP 200，之后发生的上游错误仍可能通过 JSON 的 `error` 返回。因此成功判断应同时检查 HTTP 状态、是否存在 `error`，以及是否有实际图片数据。

## 错误与重试

| 状态码 | 常见原因 | 处理方式 |
| --- | --- | --- |
| 400 | 请求体、模型或上游参数不合法；内容审核拒绝 | 查看 `error.type` / `error.message`，修正后再提交 |
| 401 | API Key 无效 | 检查鉴权 |
| 403 | 分组未开启图片能力，或模型访问受限 | 检查 Key 所属分组 |
| 404 | 路径或平台不支持 | 检查地址和渠道类型 |
| 413 | 请求体超限 | 减小输入体积 |
| 429 | 并发、额度或速率限制 | 降低并发，按 `Retry-After`（如有）等待 |
| 500 / 502 / 503 / 504 | 上游、网关、容量或超时异常 | 保留请求信息排查，避免立即重复生成 |

同步接口不返回任务 ID。需要先提交、后查询时，请改用[异步图像生成](/cn/api-reference/images/async-generation)。
