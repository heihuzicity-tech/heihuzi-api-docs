本页适用于 GPT Image 2.6。使用 2.5 请查看 [GPT Image 2.5 API](/cn/api-reference/images/gpt-image-2.5/generation)。

通过 `POST https://code.heihuzi.ai/v1/images/generations` 生成图片或 GIF 动图。验证日期：**2026-11-07**。请使用具有 GPT Image 2.6 权限的 API Key，并设置环境变量 `HEIHUZI_API_KEY`。

<RequestExample>
```bash
curl --fail-with-body --silent --show-error --max-time 600 \
  --request POST \
  --url https://code.heihuzi.ai/v1/images/generations \
  --header "Authorization: Bearer $HEIHUZI_API_KEY" \
  --header 'Content-Type: application/json' \
  --data '{
  "model": "gpt-image-2.6-flare",
  "prompt": "A simple blue ceramic cup on a white background.",
  "n": 1,
  "size": "1024x1024",
  "quality": "low",
  "output_format": "png"
}' \
  --output generation.json
```
</RequestExample>

请求会把完整响应保存到 `generation.json`，其中 `data[].b64_json` 是图片的 base64。

## 请求参数

参数名、取值和返回结构与 OpenAI 官方 `POST /v1/images/generations` 一致。下面每个取值都在正式环境实际调用过，具体组合见[已验证的参数组合](#已验证的参数组合)。

<ParamField body="model" type="string" required>
填写 `gpt-image-2.6-flare` 或 `gpt-image-2.6-sunburst`。官方要求明确填写型号；本站省略时使用 `gpt-image-2.5-flare`，不是 2.6。
</ParamField>

<ParamField body="prompt" type="string" required>
描述要生成的图片内容。
</ParamField>

<ParamField body="background" type="string">
背景。已验证 `transparent`、`opaque`、`auto`。`transparent` 配 `png` 得到透明背景的 PNG；GIF 填 `auto` 时实际返回 `opaque`。实际背景以响应里的 `background` 为准。
</ParamField>

<ParamField body="complexity" type="string">
出图前构思的程度，和画质 `quality` 互相独立。已验证 `low`、`medium`、`high`：同一提示词三档都正常出图，排版细节略有不同，输出用量相同，不另外收费。
</ParamField>

<ParamField body="frame_count" type="integer">
GIF 的帧数，只能与 `output_format: "gif"` 一起用。已验证 `2`、`4`、`9`、`12`、`16`，生成的帧数与请求一致；不填时为 9 帧。填 `17` 或在非 GIF 请求里带这个字段，返回 400。
</ParamField>

<ParamField body="frame_duration_ms" type="integer">
GIF 每帧显示的时长，单位毫秒，只用于 GIF。已验证 `20`、`100`、`200`、`500`、`2000`，生成的每帧时长与请求一致；不填时为 200。填 `105` 实际为 100 毫秒（按 10 毫秒取整）；填 `10` 返回 400。
</ParamField>

<ParamField body="moderation" type="string">
内容审核档位。已验证 `low`（较宽松）和 `auto`。
</ParamField>

<ParamField body="n" type="integer" default="1">
返回图片张数。已验证 `1`、`2`、`10`；填 `11` 返回 400。客户端请遍历实际返回的 `data` 数组。
</ParamField>

<ParamField body="output_compression" type="integer">
`jpeg`、`webp` 输出的压缩率。已验证 `jpeg` 填 `50`、`webp` 填 `0`。
</ParamField>

<ParamField body="output_format" type="string">
已验证 `png`、`jpeg`、`webp`、`gif`，两款型号都验证过，解码后的文件格式与请求一致。GIF 不支持流式，GIF 加 `stream: true` 返回 400。
</ParamField>

<ParamField body="partial_images" type="integer">
流式返回时的预览张数。已验证 `1`、`2`、`3`。实际收到的预览可能少于请求值：本次填 `3` 收到 1 张，填 `2` 收到 2 张，填 `1` 没有收到预览。预览图是 PNG。
</ParamField>

<ParamField body="quality" type="string">
已验证 `low`、`medium`、`high`、`xhigh`、`max`、`auto`，两款型号都验证过。`auto` 本次生成实际落在 `low`，结果以响应里的 `quality` 为准。
</ParamField>

<ParamField body="safety_identifier" type="string">
用于标识你这边的终端用户，响应里会原样返回。两款型号都验证过。
</ParamField>

<ParamField body="size" type="string">
已验证 `1024x1024`、`1536x1024`、`1024x1536`、`2048x2048`、`2880x2880`、`3840x2160`、自定义的 `1536x864` 和 `auto`。宽高都要是 16 的倍数，`1000x1000` 返回 400。`auto` 的返回尺寸不固定，本次出现过 `1312x1199`、`1536x1024`，需要固定尺寸时请明确填写。GIF 的 `size` 指每一帧的尺寸：不填和填 `512x512` 都输出 512×512；填 `1024x1024` 返回 400。
</ParamField>

<ParamField body="stream" type="boolean" default="false">
设置 `true` 后返回 SSE（`text/event-stream`），两款型号都验证过；省略时返回 JSON。见下方[流式返回](#流式返回)。
</ParamField>

<ParamField body="user" type="string">
官方已弃用的旧字段，建议改用 `safety_identifier`。只填 `user` 时，它会作为响应里的 `safety_identifier` 返回。
</ParamField>

## 生成 GIF 动图

下面的完整示例生成一张 9 帧、每帧 200 毫秒的 GIF，响应保存到 `rabbit.json`。

```bash
curl --fail-with-body --silent --show-error --max-time 600 \
  --request POST \
  --url https://code.heihuzi.ai/v1/images/generations \
  --header "Authorization: Bearer $HEIHUZI_API_KEY" \
  --header 'Content-Type: application/json' \
  --data '{
  "model": "gpt-image-2.6-sunburst",
  "prompt": "A small rabbit waving, simple flat illustration.",
  "quality": "low",
  "output_format": "gif",
  "frame_count": 9,
  "frame_duration_ms": 200
}' \
  --output rabbit.json
```

再把响应里的 base64 解码保存为 `rabbit.gif`：

```bash
python3 -c 'import base64, json; d = json.load(open("rabbit.json")); open("rabbit.gif", "wb").write(base64.b64decode(d["data"][0]["b64_json"]))'
```

- GIF 输出 512×512，响应里的 `output_format` 为 `gif`、`size` 为 `512x512`。
- 费用按实际输出用量计算，不随帧数平稳增加。本次 4、9、12、16 帧的输出用量分别是 555、1172、1038、1668，12 帧比 9 帧还少。

## 流式返回

```bash
curl --fail-with-body --silent --show-error --no-buffer --max-time 600 \
  --request POST \
  --url https://code.heihuzi.ai/v1/images/generations \
  --header "Authorization: Bearer $HEIHUZI_API_KEY" \
  --header 'Content-Type: application/json' \
  --data '{
  "model": "gpt-image-2.6-flare",
  "prompt": "A simple blue ceramic cup on a white background.",
  "n": 1,
  "size": "1024x1024",
  "quality": "low",
  "output_format": "png",
  "stream": true
}' \
  --output stream.txt
```

`stream.txt` 里是 SSE 事件。这个示例没有填 `partial_images`，只收到一个 `image_generation.completed` 事件，它的 `b64_json` 是最终图片，`usage` 是本次用量。填了 `partial_images` 时，完成事件之前会先收到 `image_generation.partial_image` 预览事件（带 `partial_image_index`），张数可能少于请求值。请以完成事件作为成功依据。

## 错误返回

参数不合法时返回 HTTP 400，结构与官方相同：`error` 里有 `message`、`type`、`param`、`code`。下面是填 `frame_count: 17` 的真实返回：

```json
{
  "error": {
    "code": "invalid_value",
    "message": "Invalid 'frame_count' for GIF output. Received 17. Use an integer from 2 to 16, or omit 'frame_count' to use 9.",
    "param": "frame_count",
    "type": "image_generation_user_error"
  }
}
```

本次实测返回 400 的情况：`frame_count` 超过 16、`frame_duration_ms` 小于 20、GIF 加 `stream: true`、非 GIF 请求带 `frame_count`、尺寸不是 16 的倍数、`n` 超过 10、GIF 填 `size: "1024x1024"`。这些请求没有扣费。
