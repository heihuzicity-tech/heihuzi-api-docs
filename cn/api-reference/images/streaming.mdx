---
title: "图片流式返回"
description: "Images SSE 的预览图、完成事件与错误处理。"
---

Images 接口传入 `stream: true` 时请求流式输出，需要保持连接直到收到最终结果。本接口不会因此返回可轮询的任务 ID。

默认按非流式方式接入；确认所用渠道支持流式输出后，再使用下面的请求示例。网关具备流式转发能力，不代表每个上游模型都支持 `stream` 或预览图。

先检查响应的 `Content-Type`：包含 `text/event-stream` 时按本页的 SSE 方式处理；如果渠道返回 JSON，则按普通 Images 的 `data[]` / `error` 解析。不能只根据请求里的 `stream: true` 决定解析方式。

```bash
curl --no-buffer --request POST \
  --url https://code.heihuzi.ai/v1/images/generations \
  --header "Authorization: Bearer $HEIHUZI_API_KEY" \
  --header 'Content-Type: application/json' \
  --data '{
    "model": "gpt-image-2.5-flare",
    "prompt": "一只坐在窗台上的橘猫",
    "size": "1024x1024",
    "quality": "low",
    "stream": true,
    "partial_images": 1
  }'
```

`partial_images` 使用 `0`–`3`，`0` 表示只接收最终图片。此参数描述预览数量，最终输出张数由 `n` 指定。

## 事件

| 场景 | 预览事件 | 完成事件 |
| --- | --- | --- |
| 图像生成 | `image_generation.partial_image` | `image_generation.completed` |
| 图像编辑 | `image_edit.partial_image` | `image_edit.completed` |

上表和下例展示常见的 Images 事件，base64 为占位符。原生 Images 渠道会保留上游事件，网关不保证将所有渠道的事件名和字段转换成完全相同的格式；客户端应按实际 `event` / `type` 解析，并容忍额外字段。

```text
event: image_generation.partial_image
data: {"type":"image_generation.partial_image","partial_image_index":0,"b64_json":"<preview-base64>"}

event: image_generation.completed
data: {"type":"image_generation.completed","created_at":1788998400,"b64_json":"<final-base64>","output_format":"png","size":"1024x1024"}
```

客户端应按 SSE 空行分隔事件，再解析 `data:` 中的 JSON。不要对整个流调用一次 `response.json()`，也不要把某一次网络读取当作一个完整事件。

- 预览图不是最终结果；实际预览数可能少于 `partial_images`。
- 多张输出可能出现多个完成事件，不能在收到第一张后直接丢弃剩余流。
- 忽略 SSE 注释和保活内容；不要强制依赖某个渠道一定发送 `[DONE]`。
- 流建立后仍可能收到 `error` 事件；HTTP 200 不等于生成成功。
- 连接中断且没有最终结果时，不应直接认定任务失败并无限重试。

本页适用于 `/v1/images/generations` 与 `/v1/images/edits`。Responses 使用另一种输出协议，不能将其事件解析器直接用于 Images。当前 GPT Image 2.5 官方绘图渠道的接入入口是这两个 Images 接口。
