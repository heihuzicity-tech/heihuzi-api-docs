`/v1/responses` 是 Codex / OpenAI API 调用的主推荐入口，适合文本、多模态输入和工具调用。旧版客户端可以使用 `/v1/chat/completions`，但新接入优先选择 Responses。

<RequestExample>
```bash cURL
curl --request POST \
  --url https://code.heihuzi.ai/v1/responses \
  --header 'Authorization: Bearer <token>' \
  --header 'Content-Type: application/json' \
  --data '{
    "model": "gpt-5.5",
    "input": "写一个 TypeScript debounce 函数"
  }'
```

```python Python
import requests

response = requests.post(
    "https://code.heihuzi.ai/v1/responses",
    headers={
        "Authorization": "Bearer <token>",
        "Content-Type": "application/json",
    },
    json={
        "model": "gpt-5.5",
        "input": "写一个 TypeScript debounce 函数",
    },
)

print(response.json())
```

```javascript JavaScript
const response = await fetch("https://code.heihuzi.ai/v1/responses", {
  method: "POST",
  headers: {
    "Authorization": "Bearer <token>",
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    model: "gpt-5.5",

  })
});

console.log(await response.json());
```
</RequestExample>

## Body

<ParamField body="model" type="string" required>
  Responses 文本模型 ID，例如 `gpt-5.6-sol`、`gpt-5.6-luna`、`gpt-6-astra`。以当前 Key 的 `/v1/models` 为准；使用图像工具时，图片模型填写在 `tools[].model`。
</ParamField>

<ParamField body="input" type="string | array" required>
  输入内容。可传字符串，也可传 OpenAI Responses 兼容的多模态 input 结构。
</ParamField>

<ParamField body="stream" type="boolean">
  是否启用流式响应。
</ParamField>

<ParamField body="tools" type="array">
  OpenAI Responses 兼容工具列表。图像工具使用 `type: "image_generation"`，并将 Flare 或 Sunburst 的完整 ID 放入工具的 `model` 字段。
</ParamField>

<ParamField body="temperature" type="number">
  采样温度。具体支持情况取决于当前模型和渠道。
</ParamField>

## 图像工具

直接生成图片可用 [Images](/cn/api-reference/images/gpt-image-2/generation)。需要在一次对话中组合文字和图片时，显式指定一个支持 Responses 的文本模型，再在 image_generation 工具里指定图片模型。图片生成权限仍然适用。

```json
{
  "model": "gpt-5.6-luna",
  "input": "生成一张极简蓝色 API 网关图标",
  "tools": [
    {
      "type": "image_generation",
      "model": "gpt-image-2.5-flare",
      "action": "generate",
      "size": "1024x1024",
      "quality": "low",
      "output_format": "png"
    }
  ],
  "tool_choice": {"type": "image_generation"},
  "stream": false
}
```

要使用 Sunburst，将工具内的 model 改为 `gpt-image-2.5-sunburst`。不要把 `size`、`quality`、`output_format` 写成 Responses 文本模型的参数，它们应放在图片工具对象内。

参考图输入使用 `input` 的多模态格式，例如：

```json
{
  "model": "gpt-5.6-luna",
  "input": [{
    "role": "user",
    "content": [
      {"type": "input_text", "text": "保留杯子形状，把背景改为浅蓝色"},
      {"type": "input_image", "image_url": "https://example.com/reference.png"}
    ]
  }],
  "tools": [{
    "type": "image_generation",
    "model": "gpt-image-2.5-sunburst",
    "action": "edit",
    "quality": "high",
    "output_format": "png"
  }],
  "tool_choice": {"type": "image_generation"},
  "stream": false
}
```

将示例 URL 替换成自己的可访问图片地址或完整 Data URL。客户端与渠道需要支持相应多模态和图像工具能力。

## Response

返回 OpenAI Responses 兼容结构。图片不在 Images 的 `data[]` 中，应遍历 `output[]`，查找 `type: "image_generation_call"`，对其中的 `result` 进行 base64 解码。

```json
{
  "object": "response",
  "status": "completed",
  "output": [
    {
      "type": "image_generation_call",
      "status": "completed",
      "result": "<base64-image-data>"
    }
  ]
}
```

这是字段示意，真实响应还可能包含文字、推理项、工具 ID 和用量。流式模式使用 Responses 事件，例如 `response.image_generation_call.partial_image` 与 `response.completed`，不能按 Images 的事件名解析。Responses 还涉及主文本模型的用量，不能用图片文件大小直接推算费用。

## 与 Chat Completions 的关系

- Responses 是 Codex / OpenAI 新接入的首选入口。
- Chat Completions 只作为旧版 `messages` 客户端的兼容入口。
- 两个接口都走 OpenAI-compatible 能力，但请求体和响应结构不同。
